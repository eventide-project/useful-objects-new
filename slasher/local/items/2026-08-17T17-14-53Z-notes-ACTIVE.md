## Thoughts

- A useful object is one that can used immediately upon initialization
- Dependencies must not be nil, otherwise using the object would not be possible as any use of dependencies would result in a nil reference exception
- An object shouldn't require the elaborations of a dependency injection framework to be used just to instantiate an object. An object is "useful" when it knows how to instantiate and configure itself.
- A class should contain all of its own construction logic, and shouldn't rely on a DI framework
- Dependencies have substitutes, a la Liskov substitution principle
  - Explain how [substitution principle] applies here (don't go into inheritance)
  - Any substitute is a first class implementation. So, a diagnostic implementation is of equal legitimacy of an implementation.
- Optionally, substitutes can have diagnostic instrumentation, or they can be plain old null objects — as long as the object is useful immediately upon instantiation
- Objects "do" things. Primary purpose
- The "entity" should be renamed. It should be "state", or "projected", or project, or something that better reflects its essence if possible. It's more like a wheel.
- Data objects don't do "OO", and we can make exceptions for their design.
