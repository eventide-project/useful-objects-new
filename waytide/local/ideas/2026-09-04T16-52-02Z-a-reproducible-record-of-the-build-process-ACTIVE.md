# A reproducible record of the build process

- **State:** Active
- **Tags:** [deferred]
- **Waits for:** nothing. It is actionable now.

The reference implementation plan asks for the build process to be recorded in great detail, so that it can be reproduced later. It says the `logs/` files are likely insufficient for this, so the process is recorded in a separate file as well. The purpose is to reproduce the process for future tutorials, demos, and articles, and to feed a future project where the work is explained.

Nothing has been written toward it. Three loop records exist, for the Upload, Specialized Substitute, and Consonant Predicate features. They record **deliberation** — each cycle's hinge, the options put at the gate, and the decision or the chat that resolved it. That is what a loop record is for, and it is not reproduction. A reader holding one knows why the design went the way it did. They do not know what to do to arrive at the same place.

What the record would have to carry is not settled. The plan states the requirement and the audience, and says the separate file is needed. It does not say what shape that file takes, where it lives, or what makes a record reproducible rather than merely detailed.
